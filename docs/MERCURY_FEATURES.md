# Mercury (macOS RSS 阅读器) 完整功能清单

> 本文档基于 Mercury macOS 版本（`mac` 分支）完整代码分析整理，作为 Windows 版本开发的参考基线。
> 分析日期：2026-07-13

---

## 一、订阅源管理 (Feed Management)

| 序号 | 功能 | 详细说明 |
|------|------|----------|
| 1.1 | **多格式订阅源支持** | RSS 2.0、Atom、JSON Feed 三种格式的解析与订阅 |
| 1.2 | **添加订阅源** | 通过 URL 添加，自动验证 HTTPS（不允许 HTTP），自动获取订阅源标题 |
| 1.3 | **编辑订阅源** | 修改订阅源名称和 URL |
| 1.4 | **删除订阅源** | 级联删除所有关联文章和内容数据 |
| 1.5 | **订阅源标题解析** | 多优先级：用户自定义标题 → 站点 og:site_name → HTML title → 订阅源 XML 中的 title |
| 1.6 | **OPML 导入** | 批量导入 OPML 2.0 格式的订阅源列表，支持合并/替换模式，支持"强制使用站点名"选项 |
| 1.7 | **OPML 导出** | 将所有订阅源导出为 OPML 2.0 文件 |
| 1.8 | **订阅源同步** | 自动/手动同步，可配置并发数（2-10，默认 6），15 分钟阈值防重复同步 |
| 1.9 | **智能同步** | Rate limit 检测（HTTP 429），4 小时冷却期；ATS 错误诊断探测；network timeout 配置 |
| 1.10 | **首次启动引导** | 无订阅源时自动导入内置 OPML 示例订阅源（Hacker News 热门） |
| 1.11 | **Atom URL 修复** | 自动检测 Atom entry 中多个 link 的最优 URL，修复旧版解析器的 URL 选择问题 |
| 1.12 | **Feed 解析版本追踪** | 记录每个 feed 上次使用的解析器版本，支持增量修复，避免重复处理 |

| 2.4 | **已读/未读管理** | 标记单篇、批量标记（当前查询范围）、全部标记已读/未读 |

| 2.13 | **文章日期显示** | 相对时间（最近同步时间）+ 精确日期 |
| 2.14 | **文章持久化标记** | 未读文章在"仅显示未读"模式下保留当前阅读位置（unreadPinnedEntryId） |

## 三、阅读模式 (Reader Mode)

| 序号 | 功能 | 详细说明 |
|------|------|----------|
| 3.1 | **内容提取管线** | 四阶段处理：源 HTML → Readability 清洗 → 规范化 Markdown → 渲染 HTML |
| 3.2 | **Readability 内容清洗** | 提取文章正文，去除广告/导航/侧栏，保留图片、表格、列表结构 |
| 3.3 | **规范化 Markdown 转换** | 2000+ 行自研 MarkdownConverter：支持 h1-h6、表格(GFM)、代码块、引用、列表、图片、视频/音频链接、删除线、上下标等 |
| 3.4 | **Markdown 渲染** | swift-markdown + 自研 MarkupHTMLVisitor 渲染为完整 HTML5 页面，支持 GFM 表格、任务列表、删除线、自动链接 |
| 3.5 | **三种阅读模式** | Reader 模式（清洗后内容）、Web 模式（原始网页）、双栏模式（左 Reader 右 Web） |
| 3.6 | **版本化缓存系统** | Readability(版本8) / Markdown(版本5) / ReaderHTML(版本3) 三层独立版本，仅失效层重建 |
| 3.7 | **智能重建策略** | 自动选择最省路径：缓存命中→markdown 渲染→readability 重建→完整获取 |
| 3.8 | **内容持久化** | 源 HTML、清洗 HTML、规范化 Markdown、渲染 HTML 分层存储 |
| 3.9 | **Obsidian Publish 管线** | 特殊处理 Obsidian 发布页面，直接获取 Markdown 源，解析 `![[]]` 媒体嵌入 |
| 3.10 | **阅读字体** | 可选手写体、衬线体、圆体、等宽体、系统字体、自定义字体 |
| 3.11 | **字体预览** | 实时字体预览选择器，列出所有 macOS 已安装字体 |
| 3.12 | **字体大小** | 13-28px 可调，快捷键 Cmd +/- |
| 3.13 | **行高** | 1.4-2.0 可调 |
| 3.14 | **内容宽度** | 600-1000px 可调 |
| 3.15 | **WebView 增量 DOM 更新** | 翻译结果逐段注入时不重新加载整页，保留滚动位置 |
| 3.16 | **图片/表格/列表保留** | 清洗过程保留结构化内容，不会丢失表格、列表、代码块 |
| 3.17 | **Web 导航策略** | 优先文档 base URL，退回到 entry URL，HTTP→HTTPS 自动升级 |
| 3.18 | **Base URL 修复** | 自动检测并修复缺失的文档 base URL（重新获取和解析） |
| 3.19 | **调试菜单** | 支持手动清除各层缓存强制重建（All/Readability/Markdown/ReaderHTML） |

### 5.3 摘要智能体 (Summary Agent)

| 序号 | 功能 | 详细说明 |
|------|------|----------|
| 5.3.1 | **文章摘要生成** | 一键生成 AI 摘要，支持流式输出（token-by-token 实时显示） |
| 5.3.2 | **目标语言选择** | 支持 12 种语言：英/简中/繁中/日/韩/西/法/德/葡/俄/阿/印地 |
| 5.3.3 | **详细程度控制** | 三级：简短(≥80词)/中等(≥150词)/详细(≥300词) |
| 5.3.4 | **自动摘要** | 可选开启：打开文章自动生成摘要，1 秒防抖，不重复生成已有摘要 |
| 5.3.5 | **摘要缓存/存储** | 按 entry+语言+详细程度 作为 key 持久化，2000 条上限自动淘汰 |
| 5.3.6 | **流式缓存** | 15 分钟 TTL 内存缓存，容量 64 条，当前活跃的 pin 保护 |
| 5.3.7 | **摘要面板** | 底部弹出面板，展示摘要参数和流式生成进度 |
| 5.3.8 | **手动清除** | 可清除已生成的摘要重新生成 |
| 5.3.9 | **源文本选择** | 优先使用 Reader Markdown，fallback 到文章摘要或标题 |

### 5.4 翻译智能体 (Translation Agent)

| 序号 | 功能 | 详细说明 |
|------|------|----------|
| 5.4.1 | **全文翻译** | 段落级逐段翻译，每段独立 LLM 请求 |
| 5.4.2 | **双语对照显示** | 原文和译文段落并排展示，蓝色左边框区分 |
| 5.4.3 | **段落提取** | 从渲染 HTML 提取 p/ul/ol 元素作为翻译单元 |
| 5.4.4 | **稳定段 ID** | 每段基于类型+序号+内容 SHA-256 生成确定性 ID |
| 5.4.5 | **内容哈希检测** | 翻译结果存储时记录源内容哈希，文章更新时自动失效 |
| 5.4.6 | **段级重试** | 失败的段可单独重试（mercury-action:// 协议链接） |
| 5.4.7 | **并发翻译** | 可配置 1-5 并发段翻译 |
| 5.4.8 | **增量投射** | 完成的翻译段逐段以 DOM 补丁方式注入页面，无需刷新 |
| 5.4.9 | **翻译恢复** | 支持中止后从已完成的段恢复（checkpoint 持久化） |
| 5.4.10 | **双提示策略** | 标准策略（指令跟随型模型）+ HY-MT 优化（翻译专用模型如混元） |
| 5.4.11 | **上下文感知** | 可选向前一个段的内容作为上下文注入（条件模板段） |
| 5.4.12 | **标题/作者翻译** | 合成标题作者段，翻译结果合并到双语视图头部 |

## 九、基础架构 (Infrastructure)

| 序号 | 功能 | 详细说明 |
|------|------|----------|
| 9.1 | **本地优先** | 无账号/无登录/无订阅，所有数据本地 SQLite 存储 |
| 9.2 | **隐私保护** | 零数据收集/零第三方共享，API Key Keychain 加密，AI 请求不经过代理 |
| 9.3 | **WAL 模式 SQLite** | GRDB + WAL 日志模式，支持并发读写，5 秒 busy timeout |
| 9.4 | **数据库迁移** | 25+ 顺序迁移，支持从最早版本平滑升级 |
| 9.5 | **数据库锁恢复** | SQLITE_BUSY/LOCKED 时自动回退只读模式 + 5 次重试（300ms 间隔） |
| 9.6 | **任务系统** | 通用任务队列 (TaskQueue actor)，优先级调度，并发控制，超时机制 |

## 关键架构决策（供 Windows 移植参考）

1. **Markdown 为规范格式**：文章清洗后存储为 Markdown（非 HTML），便于 LLM 输入、导出分享和后续加工
2. **分层持久化 + 独立版本化**：Readability / Markdown / ReaderHTML 三层缓存可独立失效重建
3. **DB-first 写入模式**：所有变更先写数据库再更新内存，保证一致性
4. **软删除 + 防复活**：文章软删除（isDeleted）+ 唯一索引防止同步重新插入
5. **通用任务队列**：所有异步操作（同步/AI/导出）统一通过 TaskQueue actor 调度
6. **Agent 运行时状态机**：统一的 Agent 生命周期管理（idle→waiting→requesting→generating→persisting→terminal）
7. **模板引擎**：Mustache 风格占位符 + 条件/循环段，代理 prompts 和文摘模板共用
8. **流式 Token 处理**：摘要和翻译支持流式输出，增量 DOM 更新不刷新整页
9. **Prompt 所有权分离**：模板文件是 prompts 的唯一来源，执行代码不添加/修改 prompt 文本
10. **提供商/模型归档**：软删除替代物理删除，保留用量统计数据的完整性
